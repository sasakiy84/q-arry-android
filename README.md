# Q-arry

Android端末内にフィードを登録し、記事をキューごとに読めるRSS・Atomリーダーです。

- 「フィードを追加」にサイトやフィードのHTTPS URLを入力します。サイトが公開するRSS・Atomへのリンクと、よく使われるフィードURLを確認します。
- 「設定」→「一般」→「フィードの移行（OPML）」で、OPMLからフィードを一括登録したり、登録済みの購読一覧を書き出したりできます。登録済みのURLはインポート時にスキップします。Q-arryで書き出したWebページ購読は、選択した監視範囲も読み戻せます。
- RSS・Atomが見つからない場合は、Webページから一覧を探します。候補を切り替え、上半分のハイライトと下半分の項目一覧を確認して登録できます。定期更新には選んだ範囲を使います。
- 「キュー」で分類を作り、「フィード」から所属先を選びます。一つのフィードを複数のキューに登録できます。
- 記事一覧ではフィードの情報を優先し、不足している項目はキャッシュ済みの OGP で補います。タイトルか説明がない場合は、記事ページから OGP を取得します。記事詳細では、取得できた OGP を優先します。
- 「記事」はカードを右へ引いて離すとGood、左へ引いて離すとBadを記録します。カードを十分に動かして背景の色が濃くなると確定できます。評価した記事と削除ボタンで削除した記事は、すべてのキューから外れます。
- 「設定」の「一般」で、記事カードをタップしたときにアプリ内の記事詳細を開くか、デフォルトブラウザで開くかを選べます。カードを長押しすると、もう一方の方法で開きます。
- 「設定」の「閲覧履歴」には開いた記事が、「評価履歴」にはGood・Badを記録した記事が表示されます。評価履歴からGood・Badを変更したり、評価を取り消して記事をキューに戻したりできます。評価は端末内に保存されます。
- フィード一覧や記事詳細のフィード名からフィード詳細を開くと、そのフィードの記事、配信元へのリンク、キュー設定、購読解除、お気に入りを利用できます。フィード一覧ではお気に入りやキュー未設定で絞り込み、名前順・更新順・登録順に切り替えられます。
- フィード詳細の「フィルターを設定」では、配信された記事のタイトル・説明に含まれるキーワードで記事を包含または除外できます。「キューを設定」では、このフィードのキュー別フィルターを設定できます。フィード全体とキュー別のどちらかを使います。フィード詳細の「絞り込み前を表示」から、フィード全体のフィルターをかける前の記事を確認できます。
- フィードは約12時間ごとに自動更新し、更新ボタンでも取得できます。「設定」→「一般」→「バックグラウンド通信」で、アプリを開いたときだけ更新する設定と Wi-Fi のみの設定を切り替えられます。全文の自動取得とベクトル索引の自動作成は、初期設定で充電中の非従量制回線に限ります。
- バックグラウンドの自動処理は Android のジョブで行い、電池残量が少ない間は延期します。

## 開発

JDK 21、Android SDK 36、Build Tools 36.0.0を使用します。最低対応OSはAndroid 16です。

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Debug APKは `app/build/outputs/apk/debug/app-debug.apk` に生成されます。

### 引用の選択と学習

日英の保存済み本文を文に分け、原文の UTF-16 オフセットで範囲を記録します。初期順位はタイトルとの類似度、本文との関連度、長さ、記事内の位置から決めます。表示幅と文字サイズで計測し、3行に収まる引用を表示します。引用表示は初期状態でオフです。

固定エンコーダは Bekko Static Embedding v1 の INT8・128次元版です。ONNX と ID 順の WordPiece 語彙を同梱し、合わせて約28 MBです。固定リビジョンと MIT ライセンスは同梱の `assets/quote/NOTICE.txt` に記載しています。 [モデルの配布元](https://huggingface.co/hotchpotch/bekko-static-embedding-v1/tree/c18167b8f244c1bc6de21ce9b710bac8a29c4615)

初回ビルドで固定版の ONNX を取得し、SHA-256 が一致したファイルを APK と AAB に組み込みます。同じビルド出力を使う場合は取得済みモデルを再利用します。

比較では20%の確率で候補の組をランダムに選び、ほかの比較では現在の上位候補と、得点が近く内容の異なる候補を組み合わせます。個人用の重みはゼロから始め、選択ごとにペアワイズのロジスティック損失で更新します。初期の学習率は0.2、L2正則化は0.025です。少数の選択で順位が大きく変わるのを抑えながら、初期順位と異なる好みも学べるようにしています。

比較履歴と重みは SQLite に同じトランザクションで保存します。取り消しでは更新前の重みを復元します。特徴形式が変わった場合は過去の記録を保持し、新しい形式の重みをゼロから始めます。

## 配布

`vMAJOR.MINOR.PATCH` タグでGitHub Actionsが起動します。ビルドジョブでテストとLintを実行し、別のジョブで署名済みAPK・AABをGitHub Releasesに公開します。

Q-arryのGitHubリポジトリで **Settings → Secrets and variables → Actions → Secrets** を開き、次の2件を登録します。

| 名前 | 値 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | リリース用キーストアをBase64でエンコードした文字列 |
| `ANDROID_KEYSTORE_PASSWORD` | キーストアと秘密鍵に共通のパスワード |

署名鍵のエイリアスは `qarry-release` で、RSA鍵を使います。APKとAABには同じ鍵を使うため、アップデートに備えてキーストアを保管してください。ワークフローを含むコミットに `v0.1.0` のようなタグを付けてGitHubにプッシュすると、リリースが開始します。
